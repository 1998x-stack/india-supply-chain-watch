# 印链观察：研究采编与公开案例处理规范

更新：2026-09-24。本站用于汇集真实、可追溯的产业信息，不提供按国籍给企业或个人信用评级的功能。

## 1. 事实条目的最小结构

- **发生日期 `date`**：官方批准、调查立案、措施生效或企业披露的事件日期。一个文件可能总结旧事件，不能用文件发布日替代旧事件时间。
- **原始资料发布日期 `publishedAt`**：原始公告发布日；若与事件日期不同，详情页分别列示。
- **最后核验日 `checkedAt`**：编辑实际复核资料的日期。未复核不得自动刷新。
- **来源 `sourceUrl` 和 `sourceLabel`**：优先政府公告、监管案件页、企业官网声明；媒体报道标为“媒体报道”，不要把新闻推测当成政府结论。
- **资料性质 `sourceType`**：政府原始资料、监管案件、企业公告、媒体报道或当事人自述。现有正式种子不含任何未经核验的企业投诉。
- **事实摘要 `points` 与编辑参考 `takeaway`**：分别表述，避免把推断写成官方结论。
- **核验限制 `verification`**：具体解释“已获批不代表投产”“调查不代表征税”“个人陈述未经第三方确认”等边界。

## 2. 日常核对顺序

首先核对 `app/sources/page.tsx` 收录的正式机构网站；以事件日期检索原始公告，再查后续修订、执行通知、投产披露或最终裁定。记录同一项目所有更新的前后文与相互矛盾处。对于来自公众号、论坛、短视频或匿名投稿的内容，不以转述数量代替独立证据。

## 3. 项目台账状态机

可考虑未来使用 `已获批 → 建设中 → 设备安装 → 开始生产 → 已核验量产`。每次状态变化必须附有新的、具体的可核验来源；不能因发布日期更近就自动推进状态。若来源仅是企业自述，须保持为“企业披露”而非第三方认证。

当前 `data/projects.json` 的所有项目统一为“官方公布获批”；不自动推断当前在建或已投产。

## 4. 公开投诉与更正

第一版将用户提交内容存入非公开待审队列。实名、主体授权、相关订单、原始合同和司法文书需要在合法保密与隐私前提下由编辑独立核查。公共页面不要发布私人联系方式、未公开保密文件或无法核实的群体指控。给予被提及方回应机会；保留更正、撤回时间和版本记录。当前产品还不具有完整证据上传、异议工单与多角色审校功能，不能当作已运行成熟的投诉处理系统。

## 5. 内容更新与工程发布

1. 在 `data/articles.json` 添加遵循现有 Schema 的记录，保留原始来源 URL；不要整篇复制第三方文章。
2. 在 `data/projects.json` 添加已确认的企业项目，确保对应官方公告的产品类别和企业名称。
3. 运行 `npm test`；再在装有项目依赖的环境运行 `npm run typecheck && npm run build`。
4. 由编辑手动检查数字的单位、事实时点、主体、标题与风险提示；对有争议的文章完成法律与事实复审后再发布。
5. 正式发布时，将代码提交 GitHub 并通过已配置的 Vercel 项目构建；线上页面要抽查搜索、详情、原始链接、移动端及更正入口。

**运营提醒：** 本版 JSON 是手动维护内容源，并不自动从网站实时抓取或刷新；数据越新越需要持续检查原始文件日期及版本。
